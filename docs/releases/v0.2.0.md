armsense v0.2.0 — hypervisor integration

Highly experimental: this release may or may not work, has not been
audited and is not fit for production use. It is provided "as is", without
warranty of any kind; use it at your own risk.

This tag versions the build tooling, branding and documentation that
produce armsense, a firewall/router distribution for arm64 derived from the
pfSense® Community Edition code base (Apache License 2.0). The images
attached here were built from the same pinned upstream sources as v0.1.0
(product version 2.9.0-DEVELOPMENT); what changed is how they behave under
hypervisors.

New in this release

* QEMU guest agent on by default. It starts when the hypervisor offers a
  channel: the QEMU/libvirt/Proxmox port `org.qemu.guest_agent.0`, or the
  second serial port of an Apple Virtualization VM (MacVisor). Clean
  shutdown and restart, and address readout, work from the host.
* Console menu on the first virtio console (`ttyV0.0`), which Apple
  Virtualization apps show as the VM console.
* Two disk-image flavours:
  - `armsense-<version>-arm64-<date>.qcow2`: LAN fixed at 192.168.1.1/24
    with a DHCP server (upstream default);
  - `armsense-<version>-arm64-<date>-lan-dhcp.qcow2`: LAN is a DHCP client
    too, for hypervisors whose second network has its own DHCP server
    (MacVisor, UTM, shared networks). The console menu shows the address.
* `deploy/libvirt/`: `create-vm.sh` and a domain template that create and
  start the VM on a libvirt/KVM host such as a Raspberry Pi 5, with the UEFI
  firmware without Secure Boot that the FreeBSD loader needs. Attached as
  `armsense-libvirt-v0.2.0.tar.gz`.
* Documentation: getting started on libvirt/KVM and Apple Virtualization,
  SETUP.md for building from source, release procedure.

Defaults

* Login `admin` / `armsense`, hostname `armsense`, serial console enabled,
  WAN on the first NIC (DHCP), LAN on the second.

Known limitations

* Package repositories are unsigned and point at a development server.
* PPPoE uses the mpd5 path; the upstream in-kernel driver is not available.
* Stand-ins replace the upstream repository client and unique-ID tool;
  Kea is the stock version.
* Raspberry Pi bare-metal images are not produced yet; the Pi 5 runs
  armsense as a KVM guest.
* Secure Boot must be off in the VM firmware (see deploy/libvirt/README.md).

Images are built on the FreeBSD build VM and attached to this release with
`buildvm/publish-release.sh`; `SHA256SUMS-images-v0.2.0.txt` lists their
checksums.
